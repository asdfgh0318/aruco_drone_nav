ArUco Vision GPS - Position Estimation Pipeline

Step 1: Camera Capture + ArUco Detection
Camera Input
USB Camera (1280x720 MJPG)
cap.read() → frame (BGR)
Threaded capture, single buffer, focus locked at infinity
↓
Preprocessing
Gray → CLAHE → BGR
gray → clahe.apply(gray) → cvtColor(enhanced, BGR)
~25ms — adaptive contrast for robust detection
↓
ArUco Detection
detectMarkers() → corners, ids
corners = [[x1,y1], [x2,y2], [x3,y3], [x4,y4]] # pixel coords
~85ms — bottleneck. Old API (4.6) + New API (4.9) supported
Step 2: solvePnP → Raw Pose
Pose Estimation
cv2.solvePnP(obj_pts, corners, cam_matrix, dist_coeffs)
→ rvec (3x1 axis-angle), tvec (3x1 translation)
Uses camera_params.yaml intrinsics (fx, fy, cx, cy + distortion)
Temporal consistency: IPPE_SQUARE first frame, ITERATIVE thereafter
Sanity check: discard if distance > 10m or rvec explodes
↓
tvec camera frame
Marker position in camera frame
tvec = [x, y, z] meters
Camera frame (OpenCV):
X = right in image
Y = down in image
Z = optical axis (toward marker = UP)
rvec camera frame
Marker rotation in camera frame
R_cm = Rodrigues(rvec) # 3x3 matrix
Transforms points FROM marker TO camera frame
Step 3: Position Estimation (estimate_single)
Config Loaded at Startup
R_CB_NOMINAL = [[-1, 0, 0],
  [ 0, 1, 0],
  [ 0, 0, 1]]
# cam_-X → body fwd
# cam_Y → body right
# cam_Z → body up
# det = -1 (reflection)
R_CB = R_CB_NOMINAL @ R_tilt

# R_tilt from level calibration
# tilt_y = atan(-dx / fx)
# tilt_x = atan(-dy / fy)
# R_tilt = Ry(tilt_y) @ Rx(tilt_x)
R_mw = marker_to_world(orient)

= [[cos, -sin, 0],
  [sin, cos, 0],
  [ 0, 0, -1]]
# Z flipped: ceiling marker
↓
De-tilt tvec camera frame → ideal camera frame
tvec = (R_CB_NOMINAL.T @ R_CB) @ detection.tvec
R_CB_NOMINAL.T @ R_CB = R_CB_NOMINAL.T @ R_CB_NOMINAL @ R_tilt = I @ R_tilt = R_tilt
Rotates tvec from tilted camera frame to what it would be if camera were perfectly vertical
↓
Extract Yaw camera → world
R_bw = R_mw @ R_cm.T @ R_CB_NOMINAL.T
yaw = atan2(R_bw[1,0], R_bw[0,0])
Uses R_CB_NOMINAL (no tilt) — yaw is independent of camera mounting pitch/roll
R_bw chain: body → camera (R_CB.T) → marker (R_cm.T) → world (R_mw)
det(R_bw) = -1 due to R_CB reflection → arctan2 gives CW angles
↓
Build Yaw Rotation
R_yaw = [[cos(yaw), -sin(yaw), 0],
  [sin(yaw), cos(yaw), 0],
  [ 0, 0, 1]]
↓
Position Chain camera → body → world
cam_offset_world = R_yaw @ R_CB_NOMINAL @ (-tvec)
-tvec → camera offset from marker camera frame
R_CB_NOMINAL @ → convert to body frame body frame
R_yaw @ → rotate to world world frame
↓
World Position ENU
pos = marker_world_pos + cam_offset_world
pos = [x_east, y_north, z_up] # meters, ENU
marker_world_pos from marker_map.yaml
↓
Yaw Convention
yaw_compass = degrees(yaw) - 90
atan2 with det=-1 R_bw → CW from East (0=East, 90=South)
Compass convention → CW from North (0=North, 90=East)
Offset = -90°
Step 4: Output to Flight Controller
GPS_INPUT (MAVLink)
ENU → lat/lon + yaw centidegrees
lat = origin_lat + (y_north / 111111.0)
lon = origin_lon + (x_east / (111111.0 * cos(origin_lat)))
alt = origin_alt + z_up
yaw_cd = yaw_compass * 100 # centidegrees, 0=North CW
FC params: GPS_TYPE=14, EK3_SRC1_POSXY=3, EK3_SRC1_POSZ=1 (baro)
Known Issues / Current Problem
Camera Tilt = 10° Horizontal
Position drifts ~0.6m when drone rotates in place
Root cause: With 10° camera tilt, the "level assumption" breaks down.
solvePnP computes tvec in the TILTED camera frame. The de-tilt R_tilt correction
only rotates the vector but can't undo the perspective distortion at 10°.

The original formula (before simplification) handled this correctly:
cam_in_marker = -R_cm.T @ tvec # Full rotation, handles any tilt
pos = marker_pos + R_mw @ cam_in_marker
Options:
A) Revert to full R_cm for position (abandon level assumption)
B) Fix the physical camera mount to reduce tilt
C) Use IMU pitch/roll to build a more accurate rotation for tvec
